# Development Seed Data

All fictional seed data is generated by **`server/src/scripts/seed.js`**.
Both modes are development-only. They reject production environments and
production-looking database names before connecting, and require
`SEED_CONFIRM_DB` to exactly match `MONGO_DB_NAME`. There is no production override.
The commands default to `env/server/.env.development` and `tsw_2026_dev`.

```bash
# Preview the full reset without connecting to MongoDB.
pnpm --filter server seed --dry-run

# DESTRUCTIVE: clear the confirmed development database and create everything.
pnpm seed

# Preview/add missing demo data without clearing existing development data.
pnpm --filter server seed:demo --dry-run
pnpm --filter server seed:demo
```

`seed:demo` is the same script with `--demo`. For a different development database,
set `ENV_FILE` and `SEED_CONFIRM_DB` explicitly. Dry runs describe the dataset;
they do not inspect the database or calculate exact missing-record counts.

## What you get

The full reset retains the existing standalone teams, full rosters, completed
games, claim requests, onboarding examples, Metro Spring League, and deliberate
Data Health issues. It also creates the expanded demo dataset:

- Three public leagues, each with five teams and eight players per team.
- Twenty completed home/away fixtures and four upcoming fixtures per league.
- A previous completed Demo League season with twenty games.
- Consistent frozen scores, box scores, clocked events, shot maps, replay samples,
  and materialized standings/player stats.
- Claimed player profiles, manager/player memberships, commissioners, teammates,
  a fan, and a separate social publishing operator.
- Follows between the community, leagues, and teams, so followed feeds have content.
- Fifty sample highlight posts, images, game/player/team cards, six player-game
  cards, and up to six earned milestone cards. Milestones use the real catalog
  and chronological game stats, including the previous season.
- Fictional badges and avatars served from `client/public/dev-fixtures` using
  `CLIENT_ORIGIN`, with no Cloudinary uploads or fabricated asset IDs.
- Demo League permission granted; Harborview permission unrecorded; Summit
  permission declined. Each new roster includes adults, an individual decline,
  unrecorded permission, and minors with and without a guardian record.

All generated accounts are marked `isDemo` and `isInternal` for analytics
filtering. No PostHog events are emitted by the seed itself.

## Sign in

Both commands use the same seed file. `pnpm seed` creates all four leagues;
`seed:demo` adds the three demo leagues. Use each league's owner for full league
admin access; team manager and social operator roles do not grant ownership of
all leagues.

| Account                                      | Email                          | Initial password |
| -------------------------------------------- | ------------------------------ | ---------------- |
| Metro Spring League owner (`seed` only)      | `user1@user1.com`              | `password`       |
| Demo League owner (both modes)               | `testuser@gmail.com`           | `password1!2@3#` |
| Harborview Rec League owner (both modes)     | `demo-commissioner-2@tsw.demo` | `password1!2@3#` |
| Summit City Hoops Circuit owner (both modes) | `demo-commissioner-3@tsw.demo` | `password1!2@3#` |
| Social publishing operator                   | `demo-operator@tsw.demo`       | `password1!2@3#` |
| Fan with followed content                    | `demo-fan@tsw.demo`            | `password1!2@3#` |

Additive reruns preserve existing credentials, roles, avatars, and recorded
consent. They stop on a demo email or league/team slug collision with another
account's data. Missing game pairings and supporting post types are filled
individually, including after a partially completed run. The full reset deletes
all development records, including real development Instagram connections.

## Still manual in development

- Use the operator account to connect the actual development Instagram account
  and create a draft from a rendered asset. The seed creates no OAuth credentials,
  approvals, publishing queue jobs, or fake delivery history.
- Add only handles you have verified. Seed handles are empty so generated
  captions cannot accidentally tag a real person.
- Supply matching footage for video export and record its source/rights yourself.
  YouTube replay samples and synthetic event timestamps demonstrate the UI;
  they do not represent matching footage or permission to publish it.
- Test tagged landings, downloads, and enquiries in a browser and inspect PostHog
  Dev. Do not use fictional accounts as evidence of real customer conversion.

For production, record real entities and permissions through the admin UI and
follow the deployment/migration checklist. Never run these seeds against it.
